# Reproduction guide

This document describes **what can be reproduced from the public repo today** and separates low-cost CSV replays from expensive upstream RGB/VLM data preparation. The scripts were originally executed in a Downloads-based workspace; the commands below adapt paths to the organized GitHub layout. If your original archive exists, keep it unchanged as an audit trail.

## Quick start: replay frozen evaluations (Mac/CPU)

Python 3.9+ with `numpy` suffices for the two offline analysis scripts. Use an isolated environment rather than installing into system Python.

```bash
cd ~/Downloads/temporal-belief-memory
python3 -m venv .venv
source .venv/bin/activate
python -m pip install numpy
```

**Temporal robustness** (no VLM inference):

```bash
python experiments/findingdory/statemem_temporal_stress_test.py \
  --steps results/findingdory/test_step_results.csv \
  --overall results/findingdory/test_overall.json \
  --out-dir replay_outputs/temporal_stress \
  --bootstrap 20000 --sparse-seeds 20
```

Expected safeguard: `baseline_exactly_reconstructed: true` in `replay_outputs/temporal_stress/stress_report.json`. Compare `stress_results.csv` and `stress_bootstrap.csv` with checked-in summary files. The 20,000 bootstrap draws and 20 sparse masks will take longer than a minimal syntax smoke test.

**Downstream world-state QA** (no VLM inference):

```bash
python experiments/findingdory/statemem_downstream_world_qa.py \
  --steps results/findingdory/test_step_results.csv \
  --overall results/findingdory/test_overall.json \
  --out-dir replay_outputs/downstream_qa \
  --bootstrap 20000
```

Expected rounded metrics are in `results/findingdory/downstream_qa/downstream_summary.json`. The original run used **335 query times over 44 episodes**, with all methods on the same queries. Running these commands does **not** reproduce RGB perception, the benchmark environment, or the original method-selection process; it replays frozen evidence and predictions.

## Rebuild the publication figures

```bash
python -m pip install matplotlib
python figures/generate_figures.py
```

The generation script reads committed `figures/figure_data.json`, extracted from frozen aggregate reports and bootstrap CSVs. It creates PNG (300 dpi), vector PDF, and SVG files. To refresh plot data after a genuinely new experiment, explicitly regenerate and review `figure_data.json` from the new source reports; do not silently combine an old CI with a new result.

## End-to-end FindingDory RGB run (Apple Silicon/MLX)

Full reproduction additionally needs the official FindingDory-Habitat train/val metadata, native extracted transitions, annotated RGB frame files, and the MLX Qwen2.5-VL-7B-Instruct-4bit model. The project intentionally **does not commit raw downloaded datasets, model weights, VLM caches, or proprietary checkpoint files**. Read experiment script CLI arguments before launch:

```bash
python experiments/findingdory/findingdory_rgb_statemem_temporal_calfix.py --help
```

The script imports `findingdory_rgb_statemem_integration.py` from the same directory. For a run from a working directory containing the needed metadata/data and paths, the project version can be called with explicit `--metadata-root`, `--transitions`, `--cache-dir`, `--cache-path`, and `--out-dir`. Begin with `--prepare-only`, then a small `--pilot`. A full RGB rerun can take substantial time; use the saved outputs for figure regeneration. The official validation frame selection relies on task annotation; see protocol.

### Key additional original outputs to archive

Alongside `test_overall.json` and step/transition CSVs, preserve the matching full-run `prepare_report.json`, `experiment_config.json`, `calibration_table.json`, `tuning_stay_sweep.csv`, and `tuning_recency_sweep.csv` in your *private/full* experiment archive. These are necessary to audit the precise split and train-only hyperparameter selection. They are not regenerated by the two CPU replay commands.

## LMEE local metadata and RGB pilot

The local adapter consumes 32 mini-subset JSON metadata files downloaded separately from `wangsen99/LMEE-Bench` and produces a public task index, public queries, and **separate private gold answers**. Do not read gold answer image paths during RGB frame selection. Example, with metadata already downloaded:

```bash
python experiments/lmee/lmee_mini_adapter.py \
  --root ~/Downloads/lmee_mini/lmee_bench_sub \
  --out-dir replay_outputs/lmee_adapter
```

The RGB sampler and local MLX captioning scripts are in `experiments/lmee/`; their live Hugging Face download paths must be previewed with a dry run first. A few front-camera frames prove ingestion only, not official benchmark performance. The planned 48-frame multi-object pilot has not yet produced evaluated comparative results.

## Full online benchmark (future)

The official [FindingDory Habitat](https://github.com/findingdory-benchmark/findingdory-habitat) runtime and [LMEE](https://github.com/wangsen99/LMEE) evaluation rely on Linux/NVIDIA-oriented dependencies in their released setups. **No official online StateMem integration or numeric simulator score is included in this repository yet.** On a shared cluster, check that the allocation permits this research use and begin with one baseline episode before applying any StateMem patch.

## Versioning and integrity

Commit hashes for this repository and upstream datasets/code should be recorded with final experimental runs. Avoid transferring personal absolute paths or API tokens into committed manifests. The result datasets contain many correlated per-frame observations; use episode-cluster uncertainty, not frame-level IID intervals.
